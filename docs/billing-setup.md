# Включить оплату (ЮKassa)

Код продаж уже в приложении и в сервере. Ничего из этого не работает, пока в
`.env` сервера не появятся ключи ЮKassa — это сознательно: сервер без магазина
не должен падать, он просто раздаёт всем бесплатный тариф.

## 1. Переменные на сервере

`/opt/healthroutine-food/.env` на `fam`, затем `systemctl restart healthroutine-food`:

```
YOOKASSA_SHOP_ID=<shopId из личного кабинета>
YOOKASSA_SECRET_KEY=<секретный ключ>
LICENSES_PATH=/opt/healthroutine-food/data/licenses.jsonl
ENTITLEMENTS_PATH=/opt/healthroutine-food/data/entitlements.jsonl
BILLING_PUBLIC_URL=https://food.family-pie.ru
BILLING_PRICE_MONTHLY=199
BILLING_PRICE_YEARLY=1990
BILLING_RECEIPT=0
BILLING_SELLER=ИП Тихоненко Евгений Юрьевич, ОГРНИП 326508100294665, ИНН 504414138460
BILLING_CONTACT=support@family-pie.ru
BILLING_TERMS_URL=https://family-pie.ru/driftora/terms
BILLING_PRIVACY_URL=https://family-pie.ru/driftora/privacy
```

**`BILLING_RECEIPT` — единственный переключатель, который легко поставить не туда.**
Если к магазину в ЮKassa подключена касса, платёж БЕЗ чека будет отклонён → нужен
`1` (и тогда почта покупателя обязательна). Если чеки выбиваются в другом месте,
`1` продублирует их. Правильное значение знает только владелец магазина.

Два файла из `*_PATH` должны переживать деплой. Потеря `entitlements.jsonl`
молча роняет всех платящих на бесплатный тариф до следующего запуска их
приложения; потеря `licenses.jsonl` уничтожает сами купленные подписки.

## 2. Вебхук в личном кабинете ЮKassa

HTTP-уведомления → событие `payment.succeeded` →

```
https://food.family-pie.ru/billing/yookassa/webhook
```

Этот адрес намеренно не закрыт `APP_TOKEN`: ЮKassa нечем его прислать.
Аутентификация — список IP ЮKassa, и обработчик всё равно перечитывает платёж
через API, а не верит телу уведомления.

## 3. Страница оплаты для модерации

ЮKassa смотрит на страницу, с которой идут продажи. Она уже есть:
`https://food.family-pie.ru/billing/pay` — описание услуги, цена, срок, порядок
оплаты, возврат, реквизиты продавца, контакт, ссылки на оферту и политику.
Реквизиты подставляются из `BILLING_SELLER`/`BILLING_CONTACT`, так что пустые
переменные = пустые строчки на странице, которую читает модератор.

Платный раздел оферты — §6 `legal/TERMS_OF_USE.md`; ЮKassa в получателях —
раздел «Передача третьим лицам» политики. Обе копии должны совпадать с
`lib/legal/documents.ts` (в приложении текст берётся оттуда).

## 4. Проверить на себе

1. Приложение → «Ещё» → «Настройки» → «Подписка».
2. Тариф → «Оплатить 199 ₽» → карта вводится **внутри приложения**, в ЮKassa.
3. После оплаты окно закрывается само, ключ подхватывается и активируется без
   копирования; экран показывает «Подписка активна до …».
4. Сверить на сервере: `curl -s -H "Authorization: Bearer $APP_TOKEN" \
   https://food.family-pie.ru/metrics | jq .billing` — `licenses`, `active`,
   `registrations` должны вырасти.

Если деньги списались, а ключ не пришёл (уведомление ещё в пути) — экран
«Подписка» через минуту включит подписку сам; ничего не теряется.

## 5. Чего это НЕ решает

**Продавать так внутри сборки из Google Play нельзя** — Play требует свой
биллинг для цифрового контента. Значит сборок должно быть две: сайт/RuStore — с
этим экраном, Play — без него (флаг сборки + профиль в `eas.json`). Пока такой
развилки нет, экран «Подписка» виден во всех сборках.
