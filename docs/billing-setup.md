# Включить оплату (ЮKassa)

Код продаж в проде целиком. Ничего не продаётся, пока в `.env` сервера нет ключей
ЮKassa — это сознательно: сервер без магазина не падает, он раздаёт всем
бесплатный тариф, а страница подписки остаётся читаемой (её проверяет модератор
ДО того, как магазин включат).

## Что где живёт

| Что | Где |
| --- | --- |
| Страница подписки (веб) | `family-pie.ru/driftora/subscription` — репозиторий `family-pie` |
| Страница возврата (веб) | `family-pie.ru/driftora/subscription/done` |
| Экран подписки (приложение) | «Ещё» → «Настройки» → «Подписка» |
| Создание платежа, ключи, право | `food.family-pie.ru/billing/*` — репозиторий `Driftora`, `server/` |

`/billing/pay` — это 302 на страницу сайта. Продающая страница существует в одном
экземпляре: две копии цены и правил возврата разошлись бы, и первой устарела бы
та, в которую никто не смотрит.

## 1. Переменные на сервере

`/opt/healthroutine-food/.env` на `fam`, затем `systemctl restart healthroutine-food`:

```
YOOKASSA_SHOP_ID=<shopId из личного кабинета>
YOOKASSA_SECRET_KEY=<секретный ключ>
LICENSES_PATH=/opt/healthroutine-food/data/licenses.jsonl
ENTITLEMENTS_PATH=/opt/healthroutine-food/data/entitlements.jsonl
BILLING_PUBLIC_URL=https://food.family-pie.ru
BILLING_SALES_URL=https://family-pie.ru/driftora/subscription
BILLING_WEB_ORIGINS=https://family-pie.ru,https://www.family-pie.ru
BILLING_PRICE_MONTHLY=199
BILLING_PRICE_YEARLY=1990
BILLING_RECEIPT=0
```

**`BILLING_RECEIPT` — единственный переключатель, который легко поставить не туда.**
Касса подключена к магазину → платёж БЕЗ чека будет отклонён, нужен `1` (тогда
почта покупателя обязательна на обеих страницах). Чеки выбиваются в другом месте
→ `1` их продублирует. Правильное значение знает только владелец магазина.

**`BILLING_WEB_ORIGINS` — это одновременно CORS для `/billing/*` и белый список
для `return_url`.** Убрать оттуда `family-pie.ru` значит убить кнопку на сайте;
добавить чужой домен значит разрешить уводить туда наших плательщиков.

Файлы из `*_PATH` должны переживать деплой. Потеря `entitlements.jsonl` молча
роняет всех платящих на бесплатный тариф до следующего запуска их приложения;
потеря `licenses.jsonl` уничтожает сами купленные подписки.

## 2. Вебхук в личном кабинете ЮKassa

HTTP-уведомления → событие `payment.succeeded` →

```
https://food.family-pie.ru/billing/yookassa/webhook
```

Не закрыт `APP_TOKEN` намеренно: ЮKassa нечем его прислать. Аутентификация —
список IP ЮKassa, и обработчик всё равно перечитывает платёж через API, а не
верит телу уведомления.

## 3. Что дать на модерацию

- Страница продаж: `https://family-pie.ru/driftora/subscription`
- Оферта: `https://family-pie.ru/driftora/terms` (платный раздел — §6)
- Политика: `https://family-pie.ru/driftora/privacy` (ЮKassa в получателях)

Весь текст страницы лежит в разметке, а не собирается скриптом — она читается с
выключенным JS.

## 4. Проверить оба пути

**В приложении** (браузер не открывается):

1. «Ещё» → «Настройки» → «Подписка» → тариф → «Оплатить 199 ₽».
2. Форма ЮKassa открывается в окне внутри приложения.
3. После оплаты окно закрывается само, ключ активируется без копирования.

**На сайте:**

1. `family-pie.ru` → карточка Driftora → кнопка «Подписка».
2. Тариф → «Оплатить» → ЮKassa → возврат на `…/subscription/done` с ключом.
3. Ключ ввести в приложении: «Подписка» → поле ключа → «Активировать».

**Сверить на сервере:**

```bash
curl -s https://food.family-pie.ru/billing/plans          # enabled:true
ssh fam 'set -a; . /opt/healthroutine-food/.env; set +a; curl -s -H "Authorization: Bearer $APP_TOKEN" http://127.0.0.1:8787/metrics' | jq .billing
```

`licenses`, `active`, `registrations` должны вырасти.

## 5. Аккаунтов нет — правом является КЛЮЧ

Регистрации в приложении нет и не планируется, поэтому «привязать оплату к
аккаунту» здесь означает другое:

- **Ключ — это и есть подписка.** Он выдаётся по вебхуку, живёт в
  `licenses.jsonl` и проверяется при каждой активации.
- **`X-Install-Id` — только то, к чему ключ привязан.** Заголовок генерит клиент,
  он спуфится ротацией: как счётчик годится, как право — нет.
- **Один ключ на пять установок**, самая старая вытесняется. Жёсткий отказ запер
  бы платящего вне его же нового телефона.
- **Приложение шлёт ключ на сервер при каждом запуске.** Сервер хранит только
  хеш и не может перепроверить покупку сам — именно это превращает возврат
  средств в закончившийся доступ.

Отсюда следствие, которое надо знать: **потерянный ключ восстанавливается по
`payment_id`**, который ЮKassa присылает покупателю в чеке. На странице подписки
для этого есть «Уже оплатили, но потеряли ключ?». Почта покупателя у нас НЕ
хранится — она уходит в ЮKassa для чека и всё, поэтому искать по ней нечего.

Настоящая почтовая доставка ключа (и восстановление по почте) потребует SMTP и
согласия владельца — не сделано.

## 6. Чего это НЕ решает

**Продавать так внутри сборки из Google Play нельзя** — Play требует свой биллинг
для цифрового контента. Значит сборок должно быть две: сайт/RuStore — с экраном
подписки, Play — без него (флаг сборки + профиль в `eas.json`). Развилки нет,
экран пока виден во всех сборках.
